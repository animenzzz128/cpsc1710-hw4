GOAL
Write a Python program that trains a tiny character-level recurrent neural network on ten short sentences and then generates new text one character at a time, showing how sampling temperature changes the output.

WHAT THE CODE DOES (high level)
1. Data: The training text is ten sentences defined directly in the code as a list of strings: "I like cats.", "I like dogs.", "I like noodles.", "I like tacos.", "I like books.", "I like robots.", "I like music.", "I like puzzles.", "I like pizza.", "I like coding." They are joined with "\n" into one string (143 characters, no trailing newline).
2. Turning text into numbers: One token is one character. The vocabulary is the sorted list of unique characters in the text (22 of them, including the newline and space). Each character's id is its position in that sorted list. Keep a character-to-id lookup and an id-to-character lookup.
3. Training examples: Slide a window of 40 characters over the text one character at a time. Each input is 40 character ids and the target is the id of the character that immediately follows the window. This gives 103 examples. Store them as int32 NumPy arrays.
4. Model: A Keras Sequential model with three layers in this order: an Embedding layer (vocabulary size to 32 dimensions), an LSTM layer with 128 units that returns only its final output, and a Dense layer with one output per vocabulary character and no activation (it outputs raw logits).
5. Training: Sparse categorical cross-entropy loss with from_logits=True, the Adam optimizer with learning rate 0.01, batch size 64, 20 epochs, quiet training output. Use a random seed of 1710 for TensorFlow/Keras and NumPy so runs are reproducible (named SEED at the top; setting it to None skips seeding).
6. Generating text: Start from the seed text "I like ", left-padded with spaces to 40 characters. Repeatedly feed the last 40 characters to the model, take the logits for the next character, divide them by the temperature, apply softmax, and sample one character id from that distribution using a NumPy random generator. Append the character and slide the window forward by one. A temperature of 0 or less means greedy (take the highest-scoring character). Low temperature makes the model pick its top choices almost every time; high temperature flattens the probabilities so it takes more risks.

BEHAVIOR OF THE DEMO
The program prints, from top to bottom: "Corpus length: 143"; the vocabulary list; "Num training samples: 103"; and "Final loss:" followed by the loss after the last epoch (about 0.27 in my run). Then, for each temperature in 0.1, 0.5, 0.7 and 1.0, it prints a header "=== Temperature <t> ===", the line "Top probabilities for the first generated character:", the five most likely first characters after the prompt with their probabilities as percentages with one decimal (for example "  'o': 99.8%" at temperature 0.1, using the same temperature scaling), and then one generated sample of 180 characters (the printed text includes the padded seed, so it begins with blank space and "I like ").
Across samples, low temperature (0.1) produces repetitive but mostly correct lines such as "I like pizza." and "I like puzzles.". Higher temperatures (0.7, 1.0) produce more varied lines and more invented or misspelled words such as "puzzlzs", because the sampling spreads probability over less likely characters. The model has memorized only ten sentences, so every sample has the shape "I like <word>.".

CONSTRAINTS
Use TensorFlow/Keras and NumPy in a single Python file that runs with `python generated_v1.py`.
